# SG Client 099K — SMART-подключение, автоматический резерв и реальная проверка VPN

SG Client 099K — крупное обновление системы подключения и контроля соединения.

Клиент больше не считает запущенный процесс или созданный TUN-интерфейс доказательством того, что VPN действительно работает. Теперь соединение подтверждается реальной проверкой DNS и HTTPS через туннель, а при отказе активного профиля SG Client может автоматически перейти на резервный.

Подробные инструкции:

- [полная справка по политикам, SMART и failover](docs/099K-POLICIES-GUIDE.md);
- [темы оформления «Пепел» и «Сталь»](docs/099K-THEMES-GUIDE.md).

---

## Реальная проверка VPN через TUN

Раньше ядро могло успешно запуститься, а TUN-интерфейс — появиться, даже если профиль уже не имел доступа на сервере.

Например:

- пользователь удалён на сервере;
- ключ или учётные данные больше не действуют;
- сервер принимает соединение, но не пропускает трафик;
- туннель создан, но DNS или HTTPS через него не работают.

Теперь подключение проходит несколько этапов:

```text
Запуск ядра
→ создание TUN
→ проверка DNS через TUN
→ проверка HTTPS через TUN
→ подтверждение подключения
```

Статус **«Подключено»** появляется только после успешной проверки реального доступа через VPN.

Если проверка не прошла, клиент не оставляет ложный зелёный статус и показывает причину ошибки.

---

## Понятные состояния подключения

Добавлены отдельные состояния:

- `TUN включается`;
- `Проверка доступа`;
- `TUN работает`;
- `TUN нестабилен`;
- `Переключение профиля`;
- `Не удалось подключиться`;
- `TUN отключается`.

Теперь можно отличить технически запущенный туннель от действительно работающего VPN-соединения.

## Автоматическое переключение профилей

В 099K появились именованные политики автоматического резерва.

Для каждой политики можно задать собственный порядок подключения:

```text
1. Основной профиль или группа
2. Первый резерв
3. Второй резерв
4. Дополнительные варианты
```

Клиент всегда запускает только один профиль. Следующий вариант используется после подтверждённого отказа текущего соединения.

В политике можно использовать конкретные профили или группы протоколов:

- AWG 2.0;
- AWG 3.0;
- AWG 3.1;
- VLESS Reality;
- VLESS;
- XHTTP;
- Hysteria2;
- Trojan;
- VMess;
- Shadowsocks;
- TUIC;
- AnyTLS;
- WireGuard;
- другие поддерживаемые типы.

## Настройка поведения failover

Для каждой политики доступны:

- интервал проверки соединения;
- количество ошибок подряд до переключения;
- тайм-аут одной проверки;
- время блокировки неработающего варианта;
- пауза между остановкой старого и запуском нового профиля;
- ограничение количества переключений за час;
- автоматический возврат на основной профиль;
- время стабильной работы перед возвратом.

Первый элемент списка считается основным. Остальные используются по порядку как резервные.

Одиночный кратковременный сбой не вызывает немедленного переключения: клиент учитывает заданный порог последовательных ошибок.

---

## Пошаговый мастер политик

Для быстрой настройки добавлен отдельный мастер.

Доступны готовые сценарии:

- **Домашняя сеть**;
- **Мобильный интернет**;
- **Нестабильная сеть**;
- **Строгие блокировки / другая страна**;
- **Без автоматического возврата**.

Мастер состоит из трёх шагов:

1. выбор сценария;
2. выбор основного профиля и резервов;
3. проверка результата и создание политики.

После создания все параметры можно изменить вручную.

## SMART-политики для подписок

В карточке подписки появилась команда **«Создать SMART»**.

Клиент автоматически выбирает подходящий способ создания политики в зависимости от типа подписки.

### SG-подписки — выбор по протоколам

Для SG-подписок ping не используется как основной критерий.

Пользователь выбирает до трёх протоколов в нужном порядке:

```text
AWG 3.1
→ VLESS Reality
→ Hysteria2
```

Политика привязывается к конкретной подписке и не смешивает её профили с узлами из других источников.

После обновления подписки порядок протоколов сохраняется, а SG Client использует актуальные профили соответствующих типов.

### Обычные подписки — предварительный выбор по задержке

Для обычных публичных подписок клиент может проверить задержку узлов и выбрать до трёх лучших кандидатов.

```text
Узлы подписки
→ проверка задержки
→ выбор лучших кандидатов
→ реальный запуск
→ DNS и HTTPS через TUN
```

Ping используется только для предварительного отбора.

Даже узел с минимальной задержкой не считается рабочим, пока не пройдёт реальную проверку DNS и HTTPS через туннель.

Во время массовой проверки отображаются:

- количество проверенных узлов;
- количество ответивших;
- общий прогресс;
- возможность остановить проверку;
- итоговый список выбранных кандидатов.

---

## Контроль уже работающего соединения

Проверка выполняется не только при первом запуске.

Если активный профиль теряет доступ:

1. соединение помечается как нестабильное;
2. клиент повторяет проверку;
3. после достижения заданного порога запускается failover;
4. текущий профиль останавливается;
5. запускается следующий кандидат;
6. новый профиль проходит DNS- и HTTPS-проверку через TUN.

Переключение считается завершённым только после подтверждения реального доступа.

---

## Kill Switch во время проверки и переключения

Kill Switch согласован с новой системой контроля соединения.

Теперь он:

- не отключается только из-за появления TUN;
- остаётся активным во время проверки;
- защищает трафик во время failover;
- не допускает прямой выход в интернет между профилями;
- снимает ограничения только после подтверждённого доступа через новый туннель.

## AmneziaWG 2.0, 3.0 и 3.1

Версии AmneziaWG разделены и отображаются как самостоятельные типы:

- AWG 2.0;
- AWG 3.0;
- AWG 3.1.

Для AWG 3.1 используется отдельный runtime. AWG 2.0 и AWG 3.0 продолжают работать через совместимый основной runtime.

SG Client сохраняет Endpoint и порт, полученные из профиля или подписки, и не заменяет их собственными значениями.

---

## Запуск AWG без лишнего ожидания handshake

Технический запуск AWG больше не зависит только от появления первого handshake.

Сначала проверяются:

- состояние службы;
- создание туннельного интерфейса;
- доступность DNS через туннель;
- доступность HTTPS через туннель.

Это устраняет длительное неопределённое состояние, когда интерфейс уже создан, но handshake ещё не появился.

---

## Пакетное удаление профилей и нод

Добавлено удобное удаление нескольких элементов за один раз.

Поддерживаются:

- выбор отдельных элементов через `Ctrl + клик`;
- выбор диапазона через `Shift + клик`;
- выбор всех видимых элементов через `Ctrl + A`;
- единое удаление выбранных профилей;
- единое удаление выбранных нод подписки;
- совместное удаление обычных и AWG-профилей;
- одно подтверждение с указанием количества выбранных элементов.

Пример:

```text
Выбрано профилей: 12

Удалить выбранные профили?
```

При работе с подпиской можно удалить отдельные ноды, не удаляя саму подписку.

Если удалённая нода всё ещё присутствует в источнике, она может появиться снова после следующего полного обновления подписки.

## Маршрутизация и безопасное переключение

Основная логика маршрутизации SG Client сохранена.

По-прежнему используются действия:

```text
Direct — отправить напрямую
VPN — отправить через активный профиль
Block — заблокировать
```

Сохраняются пользовательские правила, исключения из TUN и готовые схемы маршрутизации.

Режим **«Белый список РФ напрямую, остальное через VPN»** использует разрешённые российские домены и точечные сети отдельных сервисов. Общий список `geoip:ru` намеренно не используется как безусловное разрешение всего российского IP-пространства.

Для разных движков маршрутизация применяется по-разному:

- Xray, sing-box и Mihomo получают правила в создаваемом конфигурационном файле;
- AmneziaWG использует исключения из `AllowedIPs` и временные прямые маршруты через физический интерфейс.

В 099K изменена не сама модель маршрутизации, а безопасность её работы при failover:

- перед переключением сохраняется защита Kill Switch;
- текущий профиль полностью останавливается;
- временные маршруты старого AWG-профиля очищаются;
- к новому профилю применяются те же правила;
- подключение подтверждается через DNS и HTTPS;
- аварийное отключение повторно очищает оставшиеся служебные маршруты.

```text
SMART выбирает профиль
→ failover безопасно переключает его
→ маршрутизация распределяет трафик
→ DNS и HTTPS подтверждают рабочий путь
```

## Обновлённый редактор политик

Редактор автоматического переключения переработан под общий стиль SG Client.

Теперь:

- политики отображаются компактными карточками;
- выбранная политика выделяется акцентной рамкой;
- каждый приоритет находится в отдельной строке;
- первый элемент обозначается как `Основной`;
- остальные — как `Резерв`;
- перемещение и удаление находятся непосредственно в строке;
- добавление нового кандидата вынесено в отдельную область;
- убраны большие пустые таблицы и лишние рамки;
- элементы больше не конкурируют за ширину;
- нижняя панель разделена на независимые области;
- оформление согласовано со светлой и тёмной темами SG Client.

## Новые темы «Пепел» и «Сталь»

Теперь в SG Client доступны пять тем:

- **Графит**;
- **Латте**;
- **Север**;
- **Пепел**;
- **Сталь**.

### Пепел

Нейтральная тёмно-серая тема без выраженной синевы и без чистого чёрного фона. Используются мягкие графитовые поверхности, светло-серый текст и сдержанный нефритовый акцент.

Тема рассчитана на длительную работу при слабом освещении.

### Сталь

Холодная серо-стальная тема с более заметными границами, повышенным контрастом и стально-синим акцентом.

Она лучше подходит для яркого монитора или рабочего места с внешним освещением.

Для обеих тем отдельно настроены:

- фон окна, верхняя и боковая панели;
- обычные, мягкие и приподнятые поверхности;
- поля, списки и всплывающие меню;
- карточки профилей и режимов подключения;
- состояния hover, pressed, selected и disabled;
- основные, вторичные и иконковые кнопки;
- таблица соединений и маршрутные метки;
- цвета успеха, предупреждения и ошибки.

Выбранная тема применяется сразу и сохраняется после перезапуска. Она не изменяет профили, SMART, failover, Kill Switch или маршрутизацию.

## Видимый прогресс проверок

Ручные и массовые проверки больше не выполняются незаметно.

Во время проверки отображаются:

- анимированная полоса прогресса;
- текущий этап;
- состояние `Проверяется…`;
- количество обработанных узлов;
- возможность остановить длительную операцию;
- итоговый результат после завершения.

Основные этапы:

```text
Проверка ядра
→ поиск TUN
→ DNS через TUN
→ HTTPS через TUN
→ завершение
```

Результат остаётся видимым после окончания проверки.

## Диагностика переключений

SG Client фиксирует основные сведения об автоматическом переключении:

- время последнего переключения;
- причину;
- исходный профиль;
- выбранный резерв;
- количество выполненных переключений.

При ручной проверке отображаются:

- найденный TUN-интерфейс;
- результат DNS;
- результат HTTPS;
- итоговая причина ошибки.

## Безопасность подписок и обновлений

В 099K усилена защита служебных данных и процесса обновления.

Добавлены меры, которые предотвращают:

- вывод содержимого подписки в журнал при ошибке импорта;
- попадание UUID, паролей, токенов и полных ссылок в диагностический лог;
- распаковку файлов за пределы разрешённого каталога;
- запуск клиента после неполного обновления;
- смешивание файлов старой и новой версии при ошибке.

При неудачном обновлении клиент не должен запускать повреждённый или частично заменённый набор файлов.

## Главное изменение SG Client 099K

SG Client больше не ограничивается запуском выбранного профиля.

Теперь клиент:

```text
проверяет реальный доступ через TUN
→ показывает фактическое состояние
→ контролирует работающее соединение
→ автоматически выбирает резерв
→ безопасно переключает профиль
→ сохраняет маршрутизацию и Kill Switch
```

**SG Client 099K — это система контроля соединения, которая проверяет, что VPN действительно работает, и автоматически восстанавливает доступ при отказе текущего профиля.**
