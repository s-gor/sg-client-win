# SG Client 099K — проверенное подключение, SMART и автоматический резерв

SG Client 099K — крупное обновление подключения, контроля доступности и автоматического восстановления VPN.

Главное изменение: клиент больше не показывает успешное подключение только потому, что процесс запущен или в Windows появился TUN-интерфейс. Обычная нода сначала проверяется без системного TUN, а готовое соединение подтверждается DNS- и HTTPS-запросами через туннель.

## 1. Проверка сервера до создания TUN — FIX11

Для обычных Xray, sing-box и Mihomo-профилей новый порядок выглядит так:

```text
Временный локальный SOCKS
→ реальный HTTPS-запрос
→ создание системного TUN
→ DNS через TUN
→ HTTPS через TUN
→ подтверждённое подключение
```

Если выбранный сервер не отвечает и политика выключена:

- временный процесс закрывается;
- TUN не создаётся;
- режим остаётся `Off`;
- показывается сообщение **«Сервер не отвечает»**.

Если политика включена, следующий кандидат также проверяется без TUN. Системный туннель создаётся только для первого реально ответившего кандидата. Если доступных кандидатов нет, клиент показывает **«Доступные серверы не найдены»**.

Для AWG используется отдельный путь: служба, handshake, DNS и HTTPS. При провале служба очищается, а рабочий статус не выставляется.

## 2. Рабочая нода всегда видна — FIX12

После успешного ручного подключения или failover:

- фактически работающая нода становится выбранной;
- поднимается на первое место независимо от режима сортировки;
- список прокручивается к ней;
- активная нода временно остаётся видимой даже при скрывающем её фильтре;
- уведомление явно сообщает, к какой ноде подключилась политика.

После отключения закрепление снимается и возвращается обычная сортировка.

## 3. Понятный редактор политик — FIX13

Редактор автоматического переключения переработан без изменения сетевого ядра.

Добавлено:

- метка **«АКТИВНА»** на текущей политике;
- название активной политики в заголовке;
- автоматические номера для одинаковых имён;
- понятные русские названия полей вместо `Timeout`, `Cooldown` и `HTTPS URL`;
- короткие подсказки к сложным параметрам;
- предупреждения об опасных значениях;
- постоянная строка реального порядка: основной → резервы;
- простой результат без технических упоминаний временного SOCKS;
- кнопка **«Перейти к профилям»** после сохранения;
- предупреждение при закрытии с несохранёнными изменениями.

## 4. Аварийная команда «Отключить всё» — FIX9

Команда больше не ждёт завершения зависшей обычной операции. Каждое нажатие повторно:

- отменяет активную и ожидающие TUN-операции;
- отменяет незавершённое AWG-подключение;
- переводит интерфейс и конфигурацию в `Off`;
- завершает отслеживаемые процессы;
- запускает ограниченную по времени очистку TUN, AWG, прокси и Kill Switch.

Повторное нажатие остаётся доступным во время очистки.

## 5. Сортировка профилей — FIX10

Работают шесть режимов:

- исходный порядок;
- задержка: быстрее;
- название;
- источник;
- протокол;
- страна.

При сортировке по задержке готовые результаты участвуют в перестановке ещё во время массовой проверки. Обновление ограничено по частоте, чтобы список из сотен нод не перегружал интерфейс. Выделение профилей при перестановке сохраняется.

## 6. Компактная проверка задержки — FIX8/FIX9

В нижней части списка показывается компактная живая накладка:

- `X из Y` и процент;
- количество ответивших;
- текущая нода;
- движущаяся шкала;
- отдельная кнопка остановки;
- компактный итог после завершения.

Только реально проверяемая строка получает анимацию. Завершённые строки сразу показывают задержку, недоступность или ошибку.

## 7. Политики и мастер

Доступны шаблоны:

- Домашняя сеть;
- Мобильный интернет;
- Нестабильная сеть;
- Строгие блокировки / другая страна;
- Без автоматического возврата.

Политика задаёт основной профиль и резервы, частоту контроля, порог ошибок, время ожидания, cooldown, паузу между кандидатами, лимит переходов и возврат на основной профиль.

## 8. SMART для подписок

### SG-подписки

Ping не используется как основной критерий. Пользователь задаёт приоритет протоколов, а политика остаётся привязанной к конкретной подписке.

### Обычные подписки

Ping используется только для предварительного отбора кандидатов. Фактическое подключение всё равно требует предварительной проверки сервера и DNS + HTTPS через TUN.

## 9. AWG 2.0, 3.0 и 3.1

Типы разделены в интерфейсе и логике выбора. AWG 3.1 использует отдельный runtime, не подменяя AWG 2.0/3.0. Endpoint и порт сохраняются из профиля или подписки.

## 10. Kill Switch и маршрутизация

Во время запуска, проверки и failover Kill Switch не снимается преждевременно. Между профилями не должен появляться незащищённый прямой выход. Маршрутизация `Direct / VPN / Block`, пользовательские исключения и RU White List сохраняются.

## 11. Пакетное управление профилями

Поддерживаются `Ctrl + клик`, `Shift + клик`, `Ctrl + A` и удаление нескольких обычных и AWG-профилей одним подтверждением. Отдельные ноды можно удалять, не удаляя подписку.

## 12. Темы

Доступно пять тем:

- Графит;
- Латте;
- Север;
- Пепел;
- Сталь.

Темы не меняют сетевую логику, политики, Kill Switch или маршрутизацию.
