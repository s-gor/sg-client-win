# SG Client 099K — проверенное подключение, SMART и автоматический резерв

SG Client 099K перерабатывает запуск и контроль VPN-соединения. Клиент больше не считает появление процесса или TUN-интерфейса доказательством рабочего доступа: подключение подтверждается фактическими DNS- и HTTPS-запросами через туннель.

## Статус публикации

Текущий исходно-сборочный кандидат: **099K FIX16**.

```text
SG-CLIENT-099K-STEP-WIZARD-CMD-FIX16.zip
SHA-256: 4c503608ecd981d3a64930d21f7b7e9089ec1bb15bfb45f78288c5368986c57b
Размер: 104 410 072 байт
```

Это не готовый Portable. GitHub Release будет опубликован только после Windows-сборки, полного запуска тестов и проверки сетевых сценариев по [чек-листу](docs/099K-RELEASE-CHECKLIST.md).

## FIX16 — запуск AWG 2.0, AWG 3.0 и AWG 3.1

Причина общего отказа была в переходе состояния перед запуском AmneziaWG. Общий preflight переводил клиент в:

```text
EnableTun = false
ConnectionMode = off
```

Обычная ветка Xray/sing-box после проверки вызывала `BeginTunCreation`, а ветка AmneziaWG запускала Windows-службу без эквивалентного перехода. Поэтому AWG 2.0, AWG 3.0 и AWG 3.1 начинали запуск из внутреннего состояния `Off`.

Исправленный порядок:

```text
выбран AWG-профиль
→ безопасная остановка предыдущего туннеля
→ BeginTunCreation
→ запуск службы AmneziaWG
→ проверка состояния службы
→ проверка handshake
→ DNS + HTTPS через TUN
→ подтверждённое подключение
```

Ошибки теперь разделяются по стадии:

- **Не удалось запустить службу AmneziaWG**;
- **Handshake AmneziaWG не получен**;
- **Туннель AmneziaWG запущен, но DNS/HTTPS через него не работают**.

Выбор runtime не изменён: AWG 2.0/3.0 используют `bin\awg`, AWG 3.1 — `bin\awg31`. Техническая причина сохраняется в журнале, а при активной политике продолжает работать прежний failover.

Подробности: [запуск AWG 2.0/3.0/3.1](docs/099K-AWG-STARTUP-GUIDE.md).

## FIX15 — импорт SG-Gateway AmneziaWG

Полноценные `.conf` больше не отправляются ошибочно в общий импортёр URI. Перед разбором клиент удаляет невидимые управляющие и Unicode format-символы, нормализует нестандартные переводы строк и сохраняет ключи, Endpoint, Address, AllowedIPs и параметры J/S/H без изменения.

Конфигурация с `[Interface]`, `[Peer]`, `S1 = 0`, `S2 = 0` и 32-битными `H1–H4` определяется как AWG 2.0. Обычный WireGuard без AWG-параметров остаётся на стандартном пути.

Подробности: [импорт SG-Gateway AmneziaWG](docs/099K-AWG-IMPORT-NORMALIZATION-RU.md).

## FIX14 и BUILD1 — выбранная цель после импорта

После импорта новый AWG-профиль остаётся целью следующего подключения, не разрывая уже работающий туннель. Команда подключения использует зафиксированный ID выбранной строки, поэтому обновление списка не может вернуть старую ноду.

BUILD1 устранил межслойную зависимость `ConfigHandler → ProfilesViewModel`: запрос выделения передаётся через `AppEvents.ProfileRevealRequested`.

## FIX11–FIX13 — preflight, активная нода и редактор политик

- Обычная Xray/sing-box/Mihomo-нода проверяется через временный SOCKS до создания системного TUN.
- После ручного подключения или failover фактически работающая нода поднимается наверх, выделяется и становится видимой.
- Редактор политик показывает активную политику, порядок резервов, предупреждения и понятные русские названия параметров.

## FIX8–FIX10 — задержка, аварийная остановка и сортировка

- Исправлена привязка индикации проверки задержки и уменьшена накладка прогресса.
- **«Отключить всё»** не блокируется зависшей операцией и повторно запускает безопасную очистку.
- Восстановлены шесть режимов сортировки; готовые результаты задержки участвуют в перестановке во время проверки.

## SMART, failover и безопасность

Политики поддерживают конкретные профили и группы протоколов, cooldown, ограничение переходов и возврат на основной профиль. SMART для SG-подписок использует приоритет протоколов, а для обычных подписок ping служит только предварительным отбором.

Kill Switch сохраняется во время проверки и переключения. Между профилями не должен появляться незащищённый прямой выход.
