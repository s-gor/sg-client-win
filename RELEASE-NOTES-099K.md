# SG Client 099K

SG Client 099K развивает ветку 099G и добавляет автоматическое переключение профилей, SMART-политики подписок, реальную проверку доступности через TUN и переработанный интерфейс управления политиками.

## Главное

- зелёный статус подключения выставляется только после успешных DNS- и HTTPS-проверок через TUN;
- удалённый или отозванный серверный профиль больше не выглядит как рабочее подключение;
- добавлены состояния запуска, проверки, стабильной работы, нестабильности, переключения и ошибки;
- добавлены именованные failover-политики с приоритетами профилей и групп протоколов;
- добавлены готовые сценарии: домашняя сеть, мобильный интернет, нестабильная сеть, строгие блокировки и режим без автоматического возврата;
- добавлен пошаговый мастер создания политики;
- для SG-подписок SMART работает по выбранным протоколам без ping;
- для остальных подписок SMART выбирает до трёх ответивших нод по ping, после чего всё равно подтверждает реальную работу DNS и HTTPS через TUN;
- SMART-политика привязывается к конкретной подписке и не использует профили из других источников;
- добавлена индикация ручной проверки соединения и массовой SMART-проверки;
- переработан редактор политики: компактные карточки, отдельные строки приоритетов, компактные действия и единая типографика SG Client;
- добавлена отдельная поддержка AWG 3.1 runtime рядом с AWG 2.0/3.0;
- добавлены множественный выбор и пакетное удаление профилей;
- обновлены Kill Switch, очистка маршрутов, безопасность подписок и защита обновлений от Zip Slip.

## Как работает проверка подключения

Запуск ядра и появление TUN-интерфейса больше не считаются достаточным признаком рабочего VPN. Клиент выполняет реальный DNS-запрос и HTTPS-подключение через TUN. Только после успешного прохождения обеих проверок соединение получает рабочий статус.

При неудаче клиент сохраняет причину, не снимает Kill Switch и либо останавливает нерабочий профиль, либо передаёт управление failover-политике.

## SMART-политики

### SG-подписки

Пользователь выбирает до трёх протоколов в порядке приоритета. Ping не используется.

### Остальные подписки

Клиент параллельно проверяет ноды по ping, выбирает до трёх лучших ответивших вариантов и затем подтверждает реальную работоспособность через DNS и HTTPS через TUN.

## Сборка

Пакет запускается через `START-099K.cmd`. Скрипт выполняет проверку manifest, очистку временного состояния, restore закреплённым SDK, тесты ServiceLib и Windows publish.

## Статус публикации

099K оформляется как release candidate. Финальный GitHub Release и бинарные архивы должны публиковаться только после подтверждённого Windows build и финальной проверки portable-пакета.
