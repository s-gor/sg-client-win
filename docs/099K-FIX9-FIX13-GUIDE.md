# SG Client 099K FIX9–FIX13 — исправления после RC

## FIX9 — аварийная остановка

**«Отключить всё»** предназначено для выхода из запуска, проверки, failover, зависшего TUN, системного или локального прокси.

Каждое нажатие немедленно отменяет активные и ожидающие TUN-операции, незавершённое AWG-подключение, переводит режим в `Off`, завершает отслеживаемые ядра и запускает ограниченную по времени очистку TUN, AWG, прокси и Kill Switch. Повторное нажатие остаётся рабочим во время очистки.

## FIX10 — сортировка профилей

Работают режимы:

- исходный порядок;
- задержка: быстрее;
- название;
- источник;
- протокол;
- страна.

Каждый завершённый результат задержки сразу участвует в сравнении. Представление обновляется с ограничением частоты, поэтому быстрая нода поднимается до окончания проверки, а выделение профилей сохраняется.

## FIX11 — проверка до создания TUN

Для обычных профилей SG Client запускает временное ядро с локальным SOCKS-портом и выполняет реальный HTTPS-запрос без изменения системных маршрутов.

```text
Временный SOCKS
→ сервер отвечает
→ создание TUN
→ DNS + HTTPS через TUN
→ рабочий статус
```

Без политики недоступный сервер приводит к `Off` и сообщению **«Сервер не отвечает»**. С политикой следующий кандидат проверяется также без TUN. Если кандидаты закончились, показывается **«Доступные серверы не найдены»**.

AWG использует отдельный путь: служба, handshake, DNS и HTTPS. При провале служба очищается.

## FIX12 — активная нода после failover

После успешного подключения рабочий профиль становится выбранным, закрепляется первым, прокручивается в видимую область и остаётся видимым при фильтре. После отключения закрепление снимается.

Уведомление показывает конкретную ноду:

> Автопереключение: подключено к [имя ноды]

## FIX13 — редактор политик

- активная политика отмечена меткой **АКТИВНА**;
- её название повторяется в заголовке;
- порядок постоянно виден как `Основной → Резерв 1 → Резерв 2`;
- одинаковые имена автоматически получают номер;
- технические подписи заменены понятными русскими;
- опасные значения сопровождаются предупреждением;
- технические причины остаются в журнале;
- после сохранения появляется кнопка **«Перейти к профилям»**;
- закрытие с несохранёнными изменениями требует подтверждения.
