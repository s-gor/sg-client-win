# Запуск AWG 2.0, AWG 3.0 и AWG 3.1 — SG Client 099K FIX16

## Причина общего отказа

После нажатия **«Подключить»** SG Client переводит состояние в предварительную проверку:

```text
EnableTun = false
ConnectionMode = off
```

Для обычных Xray/sing-box профилей после успешного SOCKS-preflight выполнялся переход `BeginTunCreation`. Для AmneziaWG временный SOCKS неприменим, но эквивалентный переход перед созданием Windows-службы отсутствовал. Поэтому все три версии AWG запускались из внутреннего состояния `Off`.

## Исправленный порядок

```text
Выбран AWG-профиль
→ безопасная остановка предыдущего туннеля
→ BeginTunCreation
→ запуск службы AmneziaWG
→ проверка состояния службы
→ проверка handshake
→ DNS + HTTPS через TUN
→ подтверждённое подключение
```

Один и тот же путь используется для:

- AWG 2.0;
- AWG 3.0;
- AWG 3.1.

Выбор runtime не изменён: AWG 2.0/3.0 используют `bin\awg`, AWG 3.1 — `bin\awg31`.

## Сообщения об ошибках

FIX16 разделяет стадии:

- **Не удалось запустить службу AmneziaWG** — Windows-служба не установлена или не перешла в RUNNING;
- **Handshake AmneziaWG не получен** — служба работает, но сервер не подтвердил обмен;
- **Туннель AmneziaWG запущен, но DNS/HTTPS через него не работают** — handshake есть, реальный доступ через туннель не подтверждён.

Техническая причина остаётся в журнале. После ошибки клиент выполняет безопасную очистку. При активной политике используется прежний failover.

## Проверка на Windows

1. Распаковать FIX16 в новую папку.
2. Запустить `START-099K.cmd` от имени администратора.
3. По очереди проверить AWG 2.0, AWG 3.0 и AWG 3.1.
4. Для рабочего профиля подтвердить статус **«TUN работает»**.
5. Для нерабочего профиля проверить, что показана конкретная стадия отказа.
6. При активной политике проверить переход к резервной ноде.
