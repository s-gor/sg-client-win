# SG Client 099K — политики, шаблоны, SMART и failover

Политика — это именованный порядок подключения. Она выбирает один рабочий VPN-профиль; маршрутизация затем решает, какой трафик отправлять через VPN, напрямую или в блокировку.

## Базовая схема

```text
Основной профиль
→ Резерв 1
→ Резерв 2
→ дополнительные кандидаты
```

Одновременно работает только один профиль. Это не балансировка нагрузки.

## Как подтверждается подключение

Для обычной ноды:

```text
Предварительная проверка без системного TUN
→ создание TUN
→ DNS через TUN
→ HTTPS через TUN
→ рабочее состояние
```

Если предварительная проверка не прошла, TUN не создаётся. При активной политике клиент проверяет следующего кандидата. Для AWG используются handshake, DNS и HTTPS после запуска службы.

## Кандидаты политики

Можно добавить:

- конкретный профиль;
- группу протокола, например AWG 3.1 или VLESS Reality;
- SMART-кандидата конкретной подписки.

Первый элемент — основной. Остальные — резервы. Порядок всегда имеет значение.

## Параметры простыми словами

| Поле | Значение |
|---|---|
| Интервал проверки | Как часто проверять уже работающий VPN |
| Ошибок подряд | Сколько последовательных неудач требуется до переключения |
| Время ожидания | Сколько ждать одну DNS- или HTTPS-проверку |
| Не проверять повторно | Сколько времени неудачная нода исключена из новых попыток |
| Пауза между нодами | Задержка перед следующим кандидатом |
| Предел переходов в час | Защита от бесконечного цикла |
| Возвращаться на первый профиль | Попытаться позднее вернуться с резерва на основной |
| Через, мин. | Сколько резерв должен стабильно работать до возврата |

### Рекомендуемая отправная точка

Для обычной сети: интервал 10–15 секунд, 2–3 ошибки подряд, ожидание 5–8 секунд, пауза между кандидатами 1–2 секунды.

## Готовые шаблоны

### Домашняя сеть

Спокойная реакция на краткие сбои. Обычно 15 секунд, 3 ошибки и возврат на основной после стабильной работы.

### Мобильный интернет

Быстрее реагирует на смену сети и базовой станции. Подходит для LTE, 5G и раздачи с телефона.

### Нестабильная сеть

Требует больше подтверждённых ошибок и реже переключается, чтобы не прыгать между нодами при плохом Wi‑Fi.

### Строгие блокировки / другая страна

Быстро исключает заблокированный сервер и остаётся на найденном рабочем резерве без автоматического возврата.

### Без автоматического возврата

После перехода на резерв клиент остаётся на нём до ручного решения пользователя.

## Пошаговый мастер

1. Выберите шаблон.
2. Укажите основной профиль и до двух резервов.
3. Проверьте итоговый порядок и создайте политику.

После создания все параметры можно изменить вручную.

## SMART

### SG-подписка

Выбираются протоколы по приоритету. Ping не является критерием рабочего VPN. Политика не смешивает ноды из разных подписок.

### Обычная подписка

Ping помогает выбрать несколько кандидатов. Затем каждый кандидат проходит реальную проверку сервера и подключение через TUN.

## Что происходит при отказе

1. Рабочее соединение не проходит очередную проверку.
2. Клиент учитывает заданный порог ошибок.
3. Текущее соединение помечается нестабильным.
4. Kill Switch остаётся активным.
5. Текущий профиль останавливается и очищается.
6. Следующий кандидат проходит предварительную проверку.
7. Для ответившего кандидата создаётся TUN.
8. DNS и HTTPS подтверждают рабочий путь.
9. Рабочая нода поднимается наверх и становится видимой.

## Cooldown и лимит переходов

Cooldown относится к неудачной ноде: она временно не участвует в следующих попытках. Лимит переходов защищает от бесконечного цикла, когда проблема находится не в сервере, а в физической сети.

## Возврат на основной профиль

При включённом возврате клиент после заданного времени стабильной работы проверяет первый профиль. Если он снова доступен, выполняется контролируемое переключение. Для строгих блокировок возврат обычно лучше отключить.

## Редактор FIX13

- активная политика отмечена меткой **АКТИВНА**;
- одинаковые имена получают номер;
- порядок всегда виден одной строкой;
- опасные значения сопровождаются предупреждением;
- технические детали остаются в журнале;
- после сохранения появляется кнопка **Перейти к профилям**;
- несохранённые изменения защищены подтверждением закрытия.

## Частые вопросы

**Низкий ping означает рабочий VPN?** Нет. Он используется только для предварительного ранжирования.

**Почему нода временно пропущена?** Она находится в cooldown после подтверждённой ошибки.

**Почему клиент не возвращается на основную?** Возврат может быть выключен, ещё не истекло время стабильности или основной профиль по-прежнему недоступен.

**Почему политика остановилась?** Возможно, исчерпан список кандидатов или достигнут предел переходов в час.
