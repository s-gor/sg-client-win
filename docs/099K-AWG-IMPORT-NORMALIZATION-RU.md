# Импорт конфигураций SG-Gateway AmneziaWG — SG Client 099K FIX15

## Исправленная проблема

Полноценная конфигурация AmneziaWG могла попасть в общий импортёр URI-ссылок, если текст из буфера, файла или QR содержал невидимый управляющий либо форматирующий символ. В результате корректный профиль выглядел как «неподдерживаемая ссылка».

FIX15 нормализует текст до распознавания:

- удаляет `NUL` и другие встроенные управляющие символы;
- удаляет BOM, bidi marks и другие символы Unicode категории `Format`;
- преобразует `U+2028`, `U+2029` и `U+0085` в обычный перевод строки;
- сохраняет обычные `CR`, `LF` и табуляцию;
- не изменяет Base64-ключи, Endpoint, Address, AllowedIPs и значения J/S/H.

## Маршрутизация импорта

```text
[Interface] + [Peer] + параметры J/S/H/AWG3
→ окно/парсер AmneziaWG
→ точная проверка полей
→ импорт профиля
```

Обычная конфигурация WireGuard без параметров AmneziaWG остаётся на стандартном пути WireGuard.

## Зафиксированный профиль SG-Gateway

Регрессионный тест использует фактическую структуру:

- `# Access: Сергей`;
- `S1 = 0`, `S2 = 0`;
- `H1 = 3785384684`;
- Endpoint `itsec.opik.net:585`;
- маршруты `0.0.0.0/0, ::/0`.

Она должна определяться как **AmneziaWG 2.0**.

Настоящие приватные и публичные ключи в тесты не добавлены: используются фиктивные значения правильного формата.

## Что не менялось

FIX15 не меняет политики, SMART, порядок резервов, preflight, Kill Switch или саму логику failover. Изменён только входной путь импорта конфигураций WireGuard/AmneziaWG.
